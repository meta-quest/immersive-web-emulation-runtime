Host mode: GPU depth sensing (WebXR Depth Sensing, 'gpu-optimized'). A host declares what it offers in `XRHostBackend.depthSensing` (`usages`, `dataFormats`); a session that asks for 'depth-sensing' then gets the first usage and data format of its `depthSensing` preferences the host offers (required: `NotSupportedError` when there is none, optional: dropped), and `session.depthUsage` / `depthDataFormat` report them. Each visible frame IWER reads `XRHostBackend.getDepth()` (a texture array with one layer per view, its size, clip planes, `rawValueToMeters` and each depth view's pose and FOV) and `XRWebGLBinding.getDepthInformation(view)` returns an `XRWebGLDepthInformation` for that eye: the host's texture (the same object every frame), `textureType` 'texture-array', the eye's layer as `imageIndex`, and the new `projectionMatrix` and `transform` of the depth view the image was sensed from (null in the emulator). With `XRDepthStateInit.matchDepthView` (default true) and a host that implements the new `XRHostBackend.reprojectDepth(depth, matrices)`, the depth is laid out in each render view instead (IWER passes, per view, the matrix from the render view's clip space to the depth view's), and the depth information carries the view's own projection and transform, as in Chromium. `XRDepthDataFormat` gains 'unsigned-short'; `negotiateHostDepth` is exported from `iwer/host`; host mode installs `XRWebGLDepthInformation` as a global. A `getDepth` that throws is reported as `host-hook` and the frame has no depth. Hosts without `depthSensing` behave as before.
