CLI and compat fixes from the native APK device matrix. `pack` and `iwer-native compat` warn about Vite dev-server `/@fs/...` URLs baked into the build (they 404 in the APK, so the app never offers XR), naming the file and the URL and suggesting a relative `base`. `compat --trace` exits 1 when the headless run never reaches XR (the "no XR session" finding is now an error, as is a main thread that hung before XR), since the runtime only shows WebXR content. A feature-detected `WebAssembly.instantiateStreaming` is reported as info, with the same message, by both the static check and `--trace` (the `WebAssembly.instantiate` fallback runs). `run --help` marks the launch extras debug-only (`--inspect`/`--query`: debug builds or release builds packed with `--inspector`; `--inspect-brk`/`--v8-flags`: debug builds only), and `run` prints one warning line when the installed build ignores the extras passed. `install` and `run` without `--serial` (or `$ANDROID_SERIAL`) refuse when several devices are connected, and list their serials. `native.frameRate` accepts 96 and 100 Hz (Quest 3 and 3S) besides 60, 72, 80, 90 and 120. `pack`'s summary lists the manifest's uses-features (for example `com.oculus.feature.PASSTHROUGH (required)`) next to its permissions.
