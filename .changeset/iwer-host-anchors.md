Host mode: anchors from the host. New optional `XRHostBackend` hooks (`createAnchor`, `getAnchorPose`, `deleteAnchor`, `persistAnchor`, `restoreAnchor`, `erasePersistentAnchor`, `getPersistentAnchors`) let a native host keep a session's anchors: `XRFrame.createAnchor` (and `XRHitTestResult.createAnchor`) asks the host for an anchor in the base space, each `anchorSpace` takes the host's pose every frame and has none while the host cannot locate it, `anchor.delete()` and the end of the session release the host's anchors, and persistent anchors work as in Quest Browser (`requestPersistentHandle`, `persistentAnchors`, `restorePersistentAnchor`, `deletePersistentAnchor`; a delete while the same UUID is being restored rejects with `InvalidStateError`, UUIDs compare in lower case, and a host anchor's `requestPersistentHandle` rejects with `InvalidStateError` once its session ended). An anchor deleted before the frame that would hand it over rejects its promise. In host mode every anchor call on a session without the `anchors` feature rejects with `NotSupportedError`, anchors created without the hooks now settle at the next frame, and `XRAnchor` / `XRAnchorSet` are installed as globals. The emulator is unchanged.
